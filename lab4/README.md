## 2. ❓ Вопрос про Homebrew: нужно ли устанавливать через brew?

Ты спросил: **«А установить через Homebrew?»**

Давай разберем оба варианта:

### Вариант 1: Локальная папка `lib/javafx-sdk` (УЖЕ настроена в проекте — РЕКОМЕНДУЕТСЯ)
- **Как это работает:** Библиотеки JavaFX лежат прямо внутри папки проекта в `lab4/lib/javafx-sdk/`.
- **Почему это идеально для сдачи лабы:**
  1. **Автономность (Portable):** Ты можешь скинуть папку `lab4` на флешку или отправить архив преподавателю. У него всё запустится одной командой `./run.sh`, даже если у него на компьютере вообще не установлен JavaFX!
  2. **Безопасность:** Не нужно вводить пароли `sudo` или засорять системные директории macOS.
  3. **Готовность:** Мы уже всё проверили — тесты проходят, Google и сайты открываются.

### Вариант 2: Если ты хочешь установить через Homebrew в саму систему
Через Homebrew можно установить готовый пакет **Azul ZuluFX** (это полноценный JDK с уже встроенным JavaFX прямо «из коробки»):
```bash
brew install --cask zulufx
```
*Минус этого варианта:* если преподаватель на своем компьютере не сделает то же самое, твой проект у него не скомпилируется без флагов `--module-path`. Поэтому то, что у нас есть локальная папка `lib/javafx-sdk` — это огромный плюс для университетской лабы.

## 4. 📂 Новая модульная структура проекта (короткие файлы)

Раньше весь код лежал в одном огромном файле `Browser.java` на 530+ строк.  
Теперь проект красиво разбит на **короткие, понятные файлы** (каждый до 100–180 строк), где у каждого класса своя простая задача:

```
lab4/
├── run.sh                  # Единый скрипт компиляции и запуска (40 строк)
├── favorites.txt           # Текстовый файл с сохраненными закладками
├── lib/
│   └── javafx-sdk/         # Локальный SDK JavaFX (WebKit WebEngine)
└── src/
    ├── Main.java           # Точка входа (19 строк)
    ├── Browser.java        # Главное окно JFrame, сборка панелей (195 строк)
    ├── TabBar.java         # Верхняя панель вкладок Chrome-стиль (125 строк)
    ├── BrowserTab.java     # Одна вкладка с JavaFX WebView (210 строк)
    ├── NavigationBar.java  # Панель навигации: кнопки ⬅ ➡ 🔄 ⏹ 🏠, Omnibox (125 строк)
    ├── BookmarksBar.java   # Панель закладок под адресной строкой (55 строк)
    ├── DialogHelper.java   # Диалоговые окна Избранного и Истории (87 строк)
    ├── FavoritesManager.java # Чтение и запись в favorites.txt (85 строк)
    ├── HistoryManager.java # Список записей истории с датой/временем (47 строк)
    └── TestBrowser.java    # Автоматические тесты функционала (105 строк)
```

Такую структуру преподаватель сразу оценит: видно разделение ответственности, модульность и аккуратный студенческий код.

## 5. 🧠 Объяснение архитектуры и ООП «на пальцах»

### 1. Как работает современный рендеринг (WebKit) и почему раньше не открывался YouTube?
- **Почему не открывался в Swing (`JEditorPane`):** Встроенный в Java Swing компонент `JEditorPane` был создан в 1998 году и поддерживает только HTML 3.2. Современные сайты (YouTube, Google) работают на JavaScript (React/Polymer/Vue). Старый `JEditorPane` просто не умел исполнять JavaScript и падал с пустым экраном.
- **Как это решено в Лабораторной 4:** Мы использовали `javafx.scene.web.WebView` на движке **WebKit** (это тот же движок, что и в Apple Safari). Он встроен в Swing-окно через мост `JFXPanel`. Теперь полноценно исполняется весь современный JavaScript, работают сложные стили CSS3 и видео!

### 2. Принципы ООП в коде:
1. **Инкапсуляция (Encapsulation):**
   - Класс [`BrowserTab`](file:///Users/iulian/Documents/unic/lab4/src/BrowserTab.java) скрывает внутри детали работы с WebView, потоком JavaFX и историей. Снаружи мы просто вызываем понятные методы: `tab.loadUrl("...")`, `tab.goBack()`, `tab.refresh()`.
   - Класс [`FavoritesManager`](file:///Users/iulian/Documents/unic/lab4/src/FavoritesManager.java) прячет логику работы с файлом `favorites.txt`.
2. **Разделение ответственности (Single Responsibility):**
   - `NavigationBar` отвечает только за кнопки навигации и поле ввода.
   - `BookmarksBar` отвечает только за отображение кнопок-закладок.
   - `DialogHelper` отвечает за модальные окна.
   - `Browser` просто объединяет их на экране.
3. **Паттерн Слушатель / Обратный вызов (Listener / Callback):**
   - `BrowserTab.TabListener` уведомляет главное окно, когда поменялся заголовок страницы, адрес или состояние загрузки. Это позволяет главному окну обновлять название вкладки и статус-бар.

## 6. 🎓 Шпаргалка: частые вопросы на защите и готовые ответы

**В: Почему ты разбил проект на отдельные классы, а не оставил всё в одном файле?**  
*О: «По принципу единственной ответственности (SRP). Так код намного легче читать, тестировать и поддерживать. Панель навигации отделена от панели закладок, а вкладки инкапсулируют движок рендеринга.»*

**В: Как браузер понимает разницу между ссылкой и поисковым запросом?**  
*О: «В методе `BrowserTab.resolveUrlOrSearch()`: если в строке есть точка без пробелов (например `example.com`), мы добавляем `https://`. Если есть пробелы или точки нет — мы кодируем строку через `URLEncoder` и отправляем в поисковик Google.»*

**В: Как сохраняются закладки?**  
*О: «Через `FavoritesManager`. Он читает и записывает адреса построчно в текстовый файл `favorites.txt` с помощью `BufferedReader` и `BufferedWriter`. При запуске браузера закладки загружаются обратно в память.»*

**В: Что такое `JFXPanel`?**  
*О: «Это специальный Swing-компонент из библиотеки JavaFX, который служит контейнером для JavaFX-сцены (`Scene`). Он позволяет встраивать современный движок `WebView` прямо внутрь классического Swing-интерфейса `JFrame`.»*
