## 2. 👥 Как проверить чат на одном компьютере

Чтобы увидеть, как два человека переписываются и пересылают друг другу файлы:

1. Запусти первое окно: `./run.sh`
   - В верхнем блоке нажми кнопку **`Pornește Server Local 🖥️`** (запустится сервер на порту `8888`).
   - Укажи имя (например `Иван`) и нажми **`Conectare 🔌`**.
2. Открой **второй терминал** и запусти еще одно окно:
   ```bash
   cd /Users/iulian/Documents/unic/lab3 && ./run.sh
   ```
   - Во втором окне оставь IP `127.0.0.1`, порт `8888`, имя напиши `Мария` и нажми **`Conectare 🔌`**.
3. **Готово!**
   - В обоих окнах справа в списке пользователей появятся `Иван` и `Мария`.
   - Напиши сообщение от Ивана — оно мгновенно появится у Марии.
   - Мария может кликнуть правой кнопкой на сообщение и выбрать **`Reply`**, чтобы ответить с цитированием.
   - Любой из них может нажать кнопку **`Fișier 📎`**, выбрать картинку или документ и отправить — у собеседника прямо в чате появится кнопка **`📥 Descarcă`**!

## 4. 🧠 Объяснение сетей и ООП «на пальцах»

Преподаватель спросит: *«Как устроена сеть и где тут ООП?»*

### 1. Что такое Сокеты (Sockets)?
> **Простая аналогия:** Представь телефонную связь.  
> - `ServerSocket` — это коммутатор телефонной станции. Он сидит на определенном номере (порту, например `8888`) и ждет звонков методом `serverSocket.accept()`.  
> - `Socket` — это твоя телефонная трубка. Клиент звонит серверу: `new Socket("127.0.0.1", 8888)`. Как только сервер снял трубку, между ними открывается провод (потоки `InputStream` и `OutputStream`), по которому можно передавать любые данные.

### 2. Зачем нужны потоки (`Thread`)?
> Если бы у нас был только один поток, приложение бы намертво зависало при ожидании сообщения!  
> В программе работают несколько потоков:
> - **Поток интерфейса (Swing EDT):** рисует кнопки, окно и реагирует на мышку.
> - **Поток слушателя клиента (`receiverThread`):** в бесконечном цикле ждет новые сообщения от сервера: `in.readObject()`. Как только сообщение пришло, оно сразу передается в окно чата.
> - **Потоки сервера (`ClientHandler`):** для каждого подключенного клиента сервер запускает отдельный поток, чтобы общаться со всеми одновременно.

### 3. Принципы ООП в этом проекте:
- **Инкапсуляция:** класс `Message` инкапсулирует автора, текст, время, вложения файлов и цитаты. Никто не может испортить поля напрямую. Класс `ChatClient` полностью прячет работу с сокетами от окна `ChatWindow`.
- **Сериализация объектов (`Serializable`):** мы не пишем сложный самодельный парсинг строк, а используем встроенный в Java механизм сериализации: объект `Message` целиком превращается в байты и летит по сети через `ObjectOutputStream`.
- **Слабая связанность (Separation of Concerns):** сетевой код (`Server`, `ChatClient`) полностью отделен от визуального интерфейса (`ChatWindow`).

## 5. 📂 Разбор каждого файла проекта

```
lab3/src/
├── Main.java              # Точка входа в программу
├── Message.java           # Модель сообщения (текст, файл, цитата, системное)
├── Server.java            # Сервер чата (принимает подключения, делает broadcast)
├── ClientHandler.java     # Поток сервера для одного конкретного клиента
├── ChatClient.java        # Сетевой клиент (отправка текста/файлов, фоновый прием)
├── ChatWindow.java        # Графический интерфейс Swing (окно чата, кнопки, список)
└── TestNetwork.java       # Автоматический тест сетевого взаимодействия
```

1. **`Message.java`**:
   - Имеет `enum Type`: `TEXT`, `REPLY`, `FILE`, `SYSTEM`, `USER_LIST`.
   - Хранит имя файла `fileName` и массив байтов `byte[] fileData` при передаче файлов.
   - Хранит автора и цитируемый текст `replyToAuthor`, `replyToText` при ответе (Reply).
2. **`Server.java`**:
   - Слушает порт через `ServerSocket`.
   - Метод `broadcast(Message msg)` рассылает сообщение всем клиентам в списке `clients`.
   - Метод `broadcastUserList()` обновляет список активных пользователей у всех участников.
3. **`ClientHandler.java`**:
   - Наследует `Thread`.
   - В методе `run()` ждет сообщений от своего клиента и передает серверу: `server.broadcast(msg)`.
   - При отключении клиента удаляет его из списка и сообщает всем в чате.
4. **`ChatClient.java`**:
   - Подключается к серверу по сокету `new Socket(host, port)`.
   - Имеет интерфейс `MessageListener` для обратной связи с окном Swing.
   - Метод `sendFile(File f)` читает файл в массив байтов `Files.readAllBytes(f.toPath())` и отправляет его по сети.
5. **`ChatWindow.java`**:
   - Полноценное окно: подключение к серверу, цветная лента сообщений `JTextPane`, плашка ответа (Reply), кнопка сохранения истории `chat_history.txt`, кнопка отправки файлов.
   - При приеме файла создает интерактивную кнопку `📥 Descarcă` прямо в ленте сообщений.

## 6. 🛠️ Как добавить новую кнопку в чат

### Пример: добавляем кнопку «Очистить чат» (Clear Chat)

JButton btnClear = new JButton("Curăță 🧹");

## 7. 🎓 Шпаргалка для защиты

1. **Вопрос:** *Как клиенты на разных компьютерах находят друг друга?*  
   **Ответ:** Через центральный сервер (архитектура Client-Server). Каждый клиент подключается по IP-адресу сервера и порту. Сервер хранит список всех подключенных клиентов и, когда один клиент отправляет сообщение, сервер рассылает его всем остальным (Broadcast).

2. **Вопрос:** *Как реализована передача файлов?*  
   **Ответ:** Отправляющий клиент считывает файл в массив байтов `byte[]` через `Files.readAllBytes()`, упаковывает его в объект `Message` с типом `FILE` и отправляет через `ObjectOutputStream`. Получатель достает массив байтов из сообщения и при нажатии кнопки `Descarcă` сохраняет его на свой жесткий диск через `Files.write()`.

3. **Вопрос:** *Почему окно чата не зависает, когда мы ждем новые сообщения?*  
   **Ответ:** Потому что сетевой опрос вынесен в отдельный фоновый поток `receiverThread`. Он блокируется в методе `in.readObject()`, ожидая входящие байты из сокета, в то время как главный поток Swing (Event Dispatch Thread) остается свободным и мгновенно реагирует на клики мыши и ввод текста.

4. **Вопрос:** *Как реализована функция ответа на сообщение (Reply)?*  
   **Ответ:** Сообщение имеет поля `replyToAuthor` и `replyToText`. Пользователь выбирает сообщение, на которое хочет ответить, эти поля заполняются, и сообщение отправляется с типом `Message.Type.REPLY`. При отображении чат выводит стилизованную цитату над текстом ответа.
